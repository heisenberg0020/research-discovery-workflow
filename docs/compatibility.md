# 能力、兼容与验证边界

**这是指导 Agent 的 Skill，不是可一键运行科研的 Agent Harness。** 仓库版 1.1.0 保持 Workflow v1.0.0 不变。

| 项目 | 实际范围 | 不代表什么 |
| --- | --- | --- |
| Skill 文本 | `SKILL.md` 与其本地引用自包含；可显式读取 | 所有客户端都能自动发现或遵从 |
| Codex 元数据 | 随包提供 `agents/openai.yaml` | 安装工具能重启客户端或修改其注册信息 |
| Python 工具 | Python 3.10+ 标准库；安装、检查、目录准备和打包 | 内置模型、搜索服务或实验执行器 |
| 隔离 | 新上下文、干净目录和限定输入按宿主能力落实 | 准备目录能清除记忆或阻止任意旧文件读取 |
| 检索能力 | 宿主现有工具；七项上游能力可选接入 | 已捆绑第三方检索脚本、账号或付费服务 |
| 先导实验 | 冻结流程中的可选步骤，具体执行需在授权范围内 | 安装或 planning 请求默认授权训练与评测 |

## 什么得到过检查

v1.0.0 已完成标准库文件测试、元数据检查和少量虚构材料的 Agent 行为试走，范围与失败修正保留在[原始验证记录](VALIDATION.md)。没有因此证明选题质量、科研成功率或两轮优越性。

v1.1.0 新增的检查关注仓库：冻结文件未变、文档与资产链接、临时目录安装、拒绝覆盖、发行包与校验。实际本地结果与 GitHub CI 见[本版发行说明](releases/v1.1.0.md)和 [Actions](https://github.com/heisenberg0020/research-discovery-workflow/actions)。未完成的远程任务不能写成已通过。

CI 在其配置的 Python/操作系统组合上运行仓库测试；这不是在每个平台验证客户端的 Skill 加载、全流程研究或隔离效果。Windows 本地符号链接测试可能需要相应权限；不能以未执行为通过。

## 其他客户端

可以按客户端实际 Skill 导入方式使用，或显式让 Agent 读取 `SKILL.md`。目前没有对 Claude Code、Cursor 等宿主做完整兼容认证。不能直接用 Codex 元数据推断它们的工具权限、记忆行为或自动加载路径。

## 常见问题

**安装了就开始调研了吗？** 没有。安装只复制文件，准备器也只准备空目录。需要你在合适的新对话中给出 brief 和启动请求。

**是否依赖另外七个 Skill？** 不依赖。它们是可选能力映射，见[能力接入](../skills/research-discovery-workflow/references/upstream-capabilities.md)。没有它们可使用宿主已有工具。

**第一次使用没有旧成果怎么办？** 原冻结流程允许 Q6 `not_applicable`，继续 Q7。不为凑阶段虚构旧结果。

**Q7-A 还缺资源，可以汇报吗？** 可以汇报真实局部进展和缺口，不能冒称完整 Q7-B 完成。具体标准以冻结指令为准。

**第二轮一定更好吗？** 不是。第二轮合流可以保留第一轮更好的构思；重复来源不等于独立复现。
