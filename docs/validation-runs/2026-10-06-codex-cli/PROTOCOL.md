# Third-batch client and behavior smoke protocol

Prepared before the model runs, 2026-10-06. This protocol tests the frozen Workflow v1.0.0 distributed in repository v1.2.0 (`a7018d89290b5267c8825e4cfc384f27d5e53d87`). It does not amend the Workflow or establish research quality.

## Scope

One actual host path: Codex CLI 0.160.0 on macOS, using an existing ChatGPT login. Install the unchanged Skill at the test workspace's `.agents/skills/research-discovery-workflow/`; do not install globally or overwrite an existing Skill. Every workspace is newly created outside any previous research project. Only public frozen instructions and explicitly fictional fixtures enter it.

Use fresh `codex exec` invocations, no fork/resume of prior scientific chats, with `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, an explicit sandbox and captured JSONL output. Use the client's default model and record what the client reports rather than claiming a requested model identity. Remove API-key environment variables for these invocations; check that login status reports ChatGPT without reading credentials. No paid API setup, new research experiment, live paper search, training or deployment is authorized.

This is not zero-context certification. User/system Skill discovery and host instructions may still exist; skipped user configuration is not cleared pretraining, memory or an old-root read denial. Workspace-write bounds writes, not all reads. Independent route/reviewer behavior is credited only if observed; two headings or declared independence are insufficient. Network research capability is not tested here.

The workspaces are under this public repository's ignored `runs/` subtree. Its public parent `AGENTS.md` can therefore apply; this is disclosed public packaging context, not an empty-instruction environment. The new roots contain no previous scientific project files. Workers do not receive this protocol, assessment criteria, sibling cases, or the withheld old packet.

## Small fixed set of runs

| Run | Minimal input and requested work | Observation to inspect |
| --- | --- | --- |
| L0 | Skill name only; reading-only diagnostic, no scientific work | Actual entry/reference read commands, resolved local installation, honest host limits, no research output |
| B1 | Neutral theory-only brief and fictional source excerpts, no old material; first use through Q7 | Concrete relationships survive final delivery; original Q5 retained; separate substantive Q5-R; first-use Q6 branch; comparison precedes insightful final explanation |
| B2-pre | A fictional saved Q5 and current-pass packet; review/repair, with a required handoff still withheld | Exact original unchanged, actual scientific repair, no premature prior-material reading, honest pending state |
| B2-post | Only after B2-pre finishes: its outputs plus the single authorized old-result packet | Specific effects on claims, fair old/new comparison, preservation, informed continuation rather than renewed independence |
| B3 | Retained empirical main question, completed formal subproblem, no qualified main resource | Local insight is not promoted to completed overall Q7-A/Q7-B; concrete unmet dependency is explained |
| B4 | Qualified formal main question and supplied comparison packet | Substantive self-contained insight report, concrete operation/control/decision branches, no invented experiment, source or discovery history |

One attempt per listed run. No resampling low-quality answers, hidden prompt correction, model changes to obtain success, or scientific Workflow edits. An infrastructure interruption is retained and reported; repeating it requires an explicit decision. B2-post runs only after the pre-stage has actually reached a usable repair/handoff point. A timeout stops that call and preserves its logs.

Fixtures describe tasks and raw artifacts, not a grading key or desired repair. They are authored test inputs, not real literature or field evidence. The author/reviewer can know the test construction; executors receive only their named packet. B2's continuation uses a fresh executor and saved artifacts, not a claim of an uninterrupted same-session test.

## Evidence and interpretation

Save the exact prompts, command flags, client-reported environment, completed tool/agent messages, produced artifacts, failures, elapsed time and reported usage. Inspect content and event order manually; passing a keyword/headings check is not a behavioral result. Check the frozen-byte inventory and original-Q5 bytes separately. Report success, failure and untested boundaries individually, not a single scientific-validity score.

Keep raw execution logs locally in ignored `runs/`. Public copies remove personal absolute path prefixes, thread identifiers and diagnostic-only private locations with explicit replacement labels; no raw credentials, user configuration, private conversations or hidden reasoning is published. Do not paraphrase away scientific failures. Publish final responses and relevant read/write events plus a redaction account, not a manufactured transcript. Token fields mean what the client reports; unknown usage remains unknown, cached input is a subset of input and is not added again.

These observations support only the listed loading and fictional-task behaviors in this environment. They do not certify the desktop GUI, other clients, full independent discovery, real-source retrieval, novelty, empirical efficacy, success rate or two-pass superiority. A detected Workflow weakness is recorded for the user, not repaired inside the frozen range.

Assess observations separately as demonstrated, inconsistent, unobserved, or not applicable, with exact trace/artifact locations and semantic reasons. L0 explicit disk reading is not by itself proof of a host registry entry. For B1, check T/U exposure, mechanism delivery, preserved Q5 and real retrospective, absent-prior branch and comparison/report ordering. For B2, check withholding and original bytes, actual repaired operation, honest pending state and later scoped claim change. For B3, a formal local proof cannot substitute for the retained empirical object's qualified resource plan. For B4, inspect the final conversation itself and its consistency with the supplied formal comparison; do not demand a novel method from a goal that explicitly accepts a classical answer.
