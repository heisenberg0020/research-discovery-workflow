# Five-step research isolation

## Purpose and entry

Use before a new independent exploration, especially the second pass. Reduce anchoring from previous answers without discarding the user's research interests or useful process knowledge. This is an input/context boundary, not an adversarial security audit. Preserve existing projects and global configuration.

## 1. Start a genuinely fresh reasoning context

Use a new, non-forked conversation with only the neutral task brief and this workflow. Do not copy the old transcript, candidate summary, previous final report, or prior architecture. Do not instruct an already-exposed context to “forget” and call it clean.

If a new conversation cannot be created, a fresh worker with no inherited history may perform independent discovery, provided its inputs and tool access are scoped. Explain that the exposed coordinating context still exists. If neither is possible, offer an explicitly history-informed revisit, not false independence. A stronger isolation requirement may need user action; continue packaging neutral inputs while waiting.

## 2. Prepare a clean workspace

Use a new directory outside the previous research tree. Bring only:

- The domain, interests, scientific goals, negotiable boundaries and current resource facts.
- This workflow and any specifically selected neutral capability instructions.
- New public materials acquired during this pass and its own outputs.

Do not bring old project `AGENTS.md`, source trees, generated hypotheses, candidate rankings, scores, or result packages. Do not mount/link the first pass inside the second pass early. Knowing that a handoff will occur does not require reading its content now. New evidence found publicly may overlap old literature; this is not itself contamination.

The helper prepares files only. Review the **meaning** of the supplied brief: it may itself contain previous conclusions. If the user intentionally includes an earlier hypothesis, record this as a seeded/informed run; do not pretend it was discovered independently.

## 3. Check memory and inherited project instructions

Where the host supports per-run settings, disable retrieval of previous research memories and automatic previous-project context before generation. Check which parent/project instructions are actually inherited; a new folder alone may still inherit broad parent instructions.

Use per-run options rather than deleting memories, changing global settings, or uninstalling plugins. If settings cannot be inspected or controlled, state the actual limit. Do not promise cleared model pretraining, zero anchoring, or independent evidence merely from a settings request.

## 4. Scope all context sources

Allow current-run files, selected workflow instructions, relevant public search and permitted primary sources. During the independent part, do not search previous chats, personal research notes, sibling runs or a broad parent directory “for context.” Scope local file searches to named current-run subdirectories.

Inventory relevant external surfaces once: connected drive, literature library, browser sessions, workspace search, agent memory. Disable or avoid history-bearing surfaces where supported while retaining useful public research tools. Do not accidentally disable the local reading/writing tools required to execute the workflow. Apply the same boundary to delegated workers; do not send them old candidate labels or a preferred answer.

This instruction boundary does not itself enforce tool permissions. Use host permission controls where available; otherwise report instruction-only isolation. Do not build a new attack-test platform to prove isolation.

## 5. Verify the normal execution path

Confirm the run can read its brief/instructions, search public material and write its own outputs. When scoped permissions are available, use an ordinary non-content boundary check against a known old location to confirm denial; do not read the old contents as the test. Verify the effective configuration, not only the requested one. A write restriction is not a read restriction.

Record a short account of what is enforced, what is instructed only, and what is unavailable. If the host cannot guarantee old-root denial, do not claim it can. A clean directory plus scoped reading can still be useful with an honest limitation.

## Exit and later transitions

Proceed when the neutral packet and usable tools are ready and the actual isolation level is documented. If stronger isolation is essential but unavailable, explain the needed host/user action. Do not quietly weaken an explicitly required boundary.

Keep prior materials withheld through Q5-R. At Q6, the user/coordinator may copy only the authorized package into a dedicated handoff location; record the switch to reconciliation mode. Read no broader source tree. After exposure, later revisions remain informed/merged even if they return to Q1–Q5. Preserve original independent outputs.

On a resumed session or changed executor, check whether context, memory or access changed. Accidental exposure should be disclosed briefly and used to qualify independence, not erased by rerolling. Isolation of context, separation of reasoning routes, and statistical independence of evidence are three different claims.
